CSC 230 — generics in a language without generics

csc230-c-software-tools is six C99 projects, each one handing you something the language refuses to do for you.

The one to read is the generic hash map. C has no generics, so vtype.h declares a struct of function pointers — hash, equals, print, destroy — and each concrete type supplies its own. That is a vtable, written by hand. It is exactly what C++ generates behind your back, and building one yourself is the entire point of the assignment.

The calculator does the same trick one level up. number.h has two implementations, base 10 and base 25, and the Makefile decides which one links. An interface, in a language without interfaces.

Everything C++ hands you for free is a thing someone first had to build out of structs and function pointers. Doing it once by hand is why the abstraction stops feeling like magic.

CSC 246 — one problem, five machines

csc246-operating-systems runs a joke for a whole semester: solve max-subarray, then solve it again with a different concurrency primitive underneath.

  • fork and pipe across N processes
  • Java threads
  • pthreads with POSIX semaphores
  • Monitors — a mutex and condition variables
  • CUDA, on the GPU

Five implementations of one answer teaches you what no single implementation can: what each primitive is actually for, and what it costs. The CUDA file still carries the timing note in its header.

There is also a shell in there written without the standard library — no libc string functions allowed, so customStrLen and a hand-rolled atoi are in the file — and a multithreaded Scrabble server over BSD sockets with RSA challenge-response authentication in front of it. The signal handling is done properly: SIGINT flips a volatile sig_atomic_t rather than doing real work inside the handler.

CSC 474 — break it, then catch yourself doing it

csc474-network-security is the course where you write the attack and the defence as a pair.

The cryptanalysis recovers a repeating-key XOR key it was never given. The index of coincidence across the ciphertext gives you the key length statistically, before you have guessed a single character. Slice the text into that many columns, frequency-rank each one against common English letters, and the key falls out. No libraries.

The other half is a port scanner, a version of the same scanner that randomises port order to defeat anything looking for a sequential sweep, and the detector that catches both. The detector is the short one, and it holds the whole insight:

No single packet is a port scan. It is only a scan as a rate over a window — so detection is sliding-window bookkeeping, not signature matching. Randomising the port order beats a naive detector and does nothing at all against this one.

CSC 484 — an agent that moves, plans, and decides

csc484-game-ai is three layers in C++ and SFML, each built on the one below it.

Steering — arrive, align, wander, flock. Every behaviour returns linear and angular acceleration rather than setting position directly, which is the decision that makes them compose: you sum the outputs instead of letting behaviours fight over the agent.

Pathfinding — A* over a navigation graph, with the heuristic pulled out into its own unit so admissible and inadmissible ones can be swapped and raced against each other.

Decision making — a decision tree whose leaves emit actions the steering layer carries out. The tree decides, A* plans the route, steering walks it.
