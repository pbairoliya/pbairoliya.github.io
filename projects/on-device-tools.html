On-device tools

Three programs, one shared core: Apple Vision OCR and a local LLM (Ollama, gemma3:12b), wrapped in a deterministic rules layer. Nothing they read ever leaves the machine.

The problem I was actually solving

A language model is a terrible component to build on. It is nondeterministic, it drifts between runs, and it will happily invent a plausible answer. Every one of these tools runs unattended on a schedule, which means the same input has to produce the same output — a scheduled job that re-rolls its answer every night is worse than no job at all.

So the interesting engineering here isn't the prompting. It's the layer around it:

  • The model proposes; deterministic code decides. In the daily briefing the model suggests categories for a task and those suggestions are discarded — a fixed taxonomy assigns every task by keyword precedence, so the note looks identical day to day instead of being reorganised by the model's mood.
  • Append-only state stores make reruns safe. Sections are regenerated from scratch each run, so any user edit inside them would be erased. Decisions ("stop showing me this sender", "this bill is paid") are persisted outside the generated text and replayed, so a rerun is idempotent rather than destructive.
  • An index is the source of truth, not the files. The receipt pipeline writes an append-only JSONL index; pantry and expense reports are rebuilt from it every run. Re-scanning the same receipt is a fingerprint match (store + date + time), so it corrects numbers by item delta instead of double-counting.
  • Everything is tested with the world stubbed out. OCR, the model, and the Google APIs are all replaceable, so the pipeline runs end-to-end in CI with no network, no daemon and no credentials.

The three

daily-lookback

Generates a daily note from Calendar, Gmail and iMessage — what's on today, what needs a reply, what a family member mentioned that you'd otherwise miss. Runs from launchd at 00:05 with a 09:00 retry.

The hardest part was not nagging. A regenerated reminders section will resurface a bill you already paid and an email you already dismissed, forever. That took three separate mechanisms: a grow-only ignore store keyed on (sender, subject) with dates and digits stripped so siblings of a dismissed mail stay visible; paid-bill suppression keyed per billing month so next month's statement still appears; and a signature store so a commitment extracted from a message is surfaced once even when the model rewords it on the next run.

grocery-receipts

Drop a photo of any receipt into a watched folder; it comes out the other side as a line in a monthly expense report and, if it's groceries, as pantry stock. The model classifies openly — it can invent a category it has never seen and the pipeline creates the folder.

Receipts with poor ink are caught by a simple check (item sum versus printed total off by more than 10%) and held in a review folder with a checkbox; ticking it finalises the record. The watcher holds an fcntl lock so two overlapping runs can't deadlock on Apple Vision. 52 tests.

screenshot-organizer

Sorts a Desktop full of screenshots into a foldered tree by reading what's in them. The rule that shapes the whole design: existing files are never touched. The Desktop is read-only and everything is written by copying into a new tree, so the worst case of a bad classification is a misfiled copy, never a lost file.

What I'd do differently

  • The three tools share ocr.py and ollama.py by copying them between repos. That was the right call for the first week and the wrong one by the third tool; they belong in one installable package.
  • Prompts lived in source until they didn't — a prompt with real names in it is a privacy bug waiting to be published. They're configuration now.
